## 新增需求

### 需求:全局语义主题令牌
系统必须将 `The Cognitive Architect` 设计稿中的核心色彩与表面层级定义为全局语义主题令牌，并在 Tailwind 全局主题中可复用。实现必须包含 `surface`、`surface_container_low`、`surface_container_lowest`、`surface_container_high`、`primary`、`primary_container`、`on_surface`、`outline_variant` 等关键令牌。

#### 场景:初始化全局主题变量
- **当** 项目完成主题初始化并启动应用
- **那么** 开发者必须可以通过统一令牌使用上述颜色与层级，而不需要在页面内直接硬编码十六进制色值

### 需求:无分割线结构规则
系统必须禁止将 `1px solid` 实线边框作为默认分区手段，区块边界必须通过背景层级变化表达。只有在复杂数据表格的可访问性场景下，才允许使用 `outline_variant` 的 20% 透明度作为回退边界。

#### 场景:普通区块分层
- **当** 开发者实现导航区、内容区、面板区等结构分区
- **那么** 实现必须使用 `surface` 体系的背景层级差异，而不是 1px 实线边框

#### 场景:数据表格可访问性回退
- **当** 复杂表格因可访问性要求必须提供边界提示
- **那么** 实现必须使用 `outline_variant` 且透明度为 20%，并禁止使用 100% 不透明分割线

### 需求:统一交互基础样式
系统必须将 `0.375rem` 圆角作为所有交互元素基础圆角，并定义浮层阴影 `0 8px 32px rgba(25, 28, 30, 0.06)` 作为默认悬浮层深度样式。

#### 场景:交互控件创建
- **当** 开发者新增按钮、输入框、可交互卡片等元素
- **那么** 这些元素必须采用 `0.375rem` 圆角，且不得使用与规范冲突的默认直角样式

#### 场景:浮层组件渲染
- **当** 系统渲染模态框、下拉层或 Popover 等浮层
- **那么** 必须应用规范定义的扩散阴影样式以保证统一层次感
