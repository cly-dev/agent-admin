## 为什么

当前项目已接入 Tailwind CSS，但尚未建立统一、可执行的主题规范，导致后续页面实现容易出现色彩、层级、圆角、边界和组件风格不一致的问题。现在引入并固化 `The Cognitive Architect` 主题体系，可以在项目早期建立稳定的视觉与实现基线，降低后续 UI 重构成本。

## 变更内容

- 将用户提供的设计规范文档（`DESIGN (2).md`）映射为项目内可执行的主题规范与实现约束。
- 初始化 Tailwind 全局主题基础（颜色、表面层级、排版、圆角、阴影、焦点态等设计令牌）。
- 建立组件级实现约束（按钮、输入框、卡片/列表、编辑器、浮层等），统一禁止 1px 实线分隔作为默认分区手段。
- 建立 UI 开发对齐规则：新增与改造页面必须遵循主题令牌与组件规则，实现“设计即规范”。

## 功能 (Capabilities)

### 新增功能
- `cognitive-architect-theme-foundation`: 在项目中建立 `The Cognitive Architect` 的全局主题令牌与 Tailwind 主题扩展，作为所有页面与组件的统一视觉基础。
- `theme-governed-ui-implementation`: 建立组件与页面实现的主题约束规范，要求后续 UI 开发基于统一令牌、层级和交互态实现。

## 影响

- 代码与样式：`src/global.css`、Tailwind 配置、PostCSS 配置，以及后续 UI 组件样式实现方式。
- 工程规范：新增 OpenSpec 能力规范文件与任务清单，作为后续实现与评审依据。
- 设计一致性：影响全部新 UI 与迭代 UI 的实现标准，减少样式分叉与重复设计决策。
