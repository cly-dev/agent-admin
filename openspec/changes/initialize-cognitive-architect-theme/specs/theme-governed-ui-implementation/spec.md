## 新增需求

### 需求:按钮样式必须遵循主题规范
系统中的按钮实现必须遵循主题分级：Primary 按钮必须使用 `primary -> primary_container` 的 135 度渐变与白色文字；Secondary 按钮必须使用 `surface_container_highest` 背景；Tertiary 按钮必须使用透明背景与 `primary` 文字。按钮实现禁止使用默认边框分割视觉层级。

#### 场景:创建 Primary 按钮
- **当** 开发者实现主要行动按钮（CTA）
- **那么** 按钮必须呈现 `primary` 到 `primary_container` 的 135 度渐变，并使用白色文字

#### 场景:创建 Secondary/Tertiary 按钮
- **当** 开发者实现次级与弱化行动按钮
- **那么** 按钮必须按规范使用对应背景和文字语义色，且不得依赖边框塑造层级

### 需求:输入与列表组件必须遵循状态规范
输入框默认状态必须使用 `surface_container_lowest` 背景，聚焦时必须切换到 `surface_container_high` 并应用 `surface_tint` 的 2px 外发光（10% 透明度）。卡片与列表实现必须禁止 divider lines，并通过 8px 垂直留白或 hover 背景提升来表达条目分隔。

#### 场景:输入框获取焦点
- **当** 用户聚焦输入控件
- **那么** 输入框必须切换到聚焦背景并显示规范定义的外发光效果

#### 场景:列表条目分隔
- **当** 开发者实现卡片列表或数据列表
- **那么** 必须通过留白或 hover 背景变化分隔条目，并禁止使用 1px 分割线

### 需求:所有新建或改造 UI 必须基于主题令牌
系统必须要求所有新建页面和改造页面使用主题语义令牌实现颜色、层级、排版与状态；禁止直接使用标准黑色 `#000000` 作为正文色，必须使用 `on_surface` 等语义色；代码编辑区必须遵循深色编辑面板规则。

#### 场景:实现新页面
- **当** 团队新增页面或重大改造现有页面
- **那么** 实现必须基于主题令牌完成样式，不得绕过主题体系直接硬编码通用视觉值

#### 场景:实现编辑器区域
- **当** 页面包含 Skill/Prompt 等代码编辑区
- **那么** 编辑区必须使用 `inverse_surface` 深色背景与指定等宽字体栈及语法高亮语义色
